# 知识配置后台设计稿

- 日期：2026-05-25
- 主题：将 FAQ / 规则 / 话术 从固定文件导入，迁移为后台可配置的知识内容管理能力
- 状态：已完成方案确认，待用户审阅后进入实现

## 1. 背景与目标

当前项目中的 FAQ / 规则 / 话术 主要依赖固定文件与种子脚本导入。这个模式已经不适合持续运营，主要问题有：

1. 业务人员无法直接在后台维护内容。
2. 内容修改后是否进入 AI 检索链路，不够透明。
3. 缺少面向后台的变更历史与失败排查能力。
4. 文档、规则、Skill、workflow 等治理资料容易滞后于真实实现。

本次改造目标：

1. 新增后台 `知识配置` 入口，用于直接管理 FAQ / 规则 / 话术。
2. 将三类内容统一按“单条内容”管理。
3. 新建、编辑、启停均在后台完成，不再依赖固定文件作为运行时主入口。
4. 每条内容都展示 AI 可读状态，即是否成功写入向量检索链路。
5. 每条内容都保留变更历史，并支持失败后手动重试同步。
6. 将文档同步更新作为正式交付项纳入实施范围。

## 2. 范围

### 2.1 本次纳入范围

1. 后台新增 `知识配置` 页面与接口。
2. 管理对象为：
   - 常见问答
   - 门店规则
   - 回复话术
3. 支持：
   - 列表查询
   - 搜索

4. 内容保存后自动进入 AI 同步流程。
5. 后台展示同步状态、最近同步时间、失败原因。

### 2.2 本次不纳入范围

1. 草稿 / 发布双态
2. 富文本编辑器
3. 批量编辑与批量同步
4. 历史版本一键回滚
5. 自动分类直接替代人工选择
6. 新建独立“内容主表”并彻底重构知识存储体系

## 3. 内容分类定义

为了避免后台使用者不知道该写进哪里，前台不直接强调 `FAQ / 规则 / 话术` 术语，而是展示更直白的中文分类：

1. `常见问答`
   - 适合短问短答
   - 回答客户经常咨询的问题
   - 例如：是否开发票、配送范围、保存时长、图片与实物差异

2. `门店规则`
   - 适合稳定、明确、带约束的业务规则
   - 例如：退款规则、改期规则、配送时段规则、定制限制、售后边界

3. `回复话术`
   - 适合表达方式、安抚模板、推荐话术、成交引导
   - 例如：节日推荐开场、催单安抚、转人工前安抚、缺货替代推荐

后台录入时由用户手动选择分类，但系统提供 `分类建议` 与 `建议原因`。

## 4. 交互方案

本次采用方案 B 的总体方向，但页面交互不使用左右并列的常驻双栏，而是：

1. 主页面：`列表工作台`
2. 新建：`右侧抽屉`
3. 编辑：`右侧抽屉`
4. 历史、AI 同步状态、失败原因、重试动作：在抽屉中分区展示

这样可以兼顾：

1. 主页面对全局状态的可见性
2. 编辑体验的一致性
3. 避免后台宽度不足导致左右区域都展示不全

## 5. 页面结构

### 5.1 主页面：知识配置列表

顶部工具栏包含：

1. 分类切换：`常见问答 / 门店规则 / 回复话术`
2. 搜索框：搜索标题、关键词、正文片段
3. 启用状态筛选：`全部 / 启用中 / 已停用`
4. AI 可读状态筛选：`全部 / 已入向量 / 同步中 / 同步失败 / 未同步`
5. 主按钮：`新建内容`

列表每一行展示：

1. 标题
2. 一行摘要
3. 分类
4. 启用状态
5. AI 可读状态
6. 最近同步时间
7. 最近修改时间
8. 主操作入口

主操作控制在三类：

1. `查看 / 编辑`
2. `重试同步`
3. `停用 / 启用`

### 5.2 右侧抽屉

抽屉分为四个分区：

#### A. 基本信息

1. 标题
2. 分类
3. 系统建议分类
4. 建议原因
5. 启用状态

#### B. 正文与关键词

1. 内容正文
2. 关键词
3. 优先级

#### C. AI 同步状态

1. 当前状态：`已入向量 / 同步中 / 同步失败 / 未同步`
2. 最近同步时间
3. 最近失败原因
4. `重新同步` 按钮
5. 同步中时显示加载动效

#### D. 变更历史

默认展示最近 5 条：

1. 谁改的
2. 修改时间
3. 修改字段摘要
4. 当次同步是否成功

并提供 `查看全部历史` 入口。

### 5.3 新建与编辑共用抽屉

新建与编辑使用同一套结构：

1. 新建时标题显示 `新建内容`
2. 编辑时标题显示 `编辑内容`
3. 保存按钮文案根据场景变化
4. AI 同步状态区域展示对应的真实状态

## 6. 表单校验

### 6.1 必填字段

以下字段必须填写：

1. 标题
2. 分类
3. 内容正文

以下字段建议必填，但允许系统提供默认值：

1. 关键词
   - 可根据标题与正文自动生成初始值
2. 优先级
   - 默认值建议为 `50`

### 6.2 校验规则

1. 标题不能为空，且不能全为空格
2. 正文不能为空，且不能全为空格
3. 分类必须明确选中
4. 关键词总长度应有上限
5. 优先级必须是合法数字区间
6. 停用内容不能展示成与启用状态矛盾的可用状态文案

### 6.3 交互反馈

1. 前端先做即时校验
2. 校验不通过时，字段下方显示中文提示
3. 不依赖仅用 toast 通知

## 8. 状态设计

AI 可读状态定义如下：

1. `pending`
   - 内容已写入主表，等待进入同步流程
2. `syncing`
   - 正在写入向量检索链路
3. `success`
   - 已写入成功，AI 可检索
4. `failed`
   - 同步失败，需查看原因或重试

### 8.1 状态流转

1. 新建 / 编辑保存后：`pending`
2. 开始同步：`syncing`
3. 同步成功：`success`
4. 同步失败：`failed`
5. 用户点击重试：重新进入 `syncing`

## 9. 服务层设计

### 9.1 KnowledgeAdminService

职责：

1. 列表查询
2. 详情读取
3. 新建内容
4. 编辑内容
5. 启用 / 停用
6. 分类建议生成
7. 历史查询

说明：

- 这层只负责后台内容管理语义
- API 层不直接拼装复杂业务逻辑

### 9.2 KnowledgeSyncService

职责：

1. 将指定知识内容同步到现有向量检索链路
2. 回写 `vector_sync_status`
3. 回写 `vector_synced_at`
4. 记录 `vector_sync_error`
5. 处理重试逻辑

说明：

- 这层只负责 AI 可读状态与向量同步
- 不新造一套独立知识存储系统

## 10. 保存与重试链路

### 10.1 保存链路

1. API 收到保存请求
2. 参数校验
3. `KnowledgeAdminService` 写入 `knowledge_base`
4. 先标记为 `pending`
5. 启动同步流程并切换为 `syncing`
6. 同步成功则改为 `success`
7. 同步失败则改为 `failed` 并记录错误
8. 同时写入 `content_change_history`

### 10.2 重试链路

1. 校验条目存在
2. 触发 `KnowledgeSyncService`
3. 状态切换为 `syncing`
4. 根据结果更新为 `success` 或 `failed`
5. 写入历史记录

至少同步以下内容：

1. `LOGBOOK.md`

2. `项目进度与配置清单.md`
   - 更新最后日期、能力清单、已知问题
3. `AGENTS.md`
   - 更新关键路径、命令速查、知识配置入口与旧入口退役说明
4. 相关 Skill / Rules / Workflow 文档
   - 如果本次实现改变了工作方式、检查点、提交流程或关键入口，必须同步修改

1. 文档必须和真实实现同轮更新

3. 后续任何扩展也应延续这条治理纪律

推荐按以下形态实现：

1. 主页面使用列表工作台
2. 新建与编辑都使用右侧抽屉
3. FAQ / 规则 / 话术统一按单条内容管理

5. 每条内容显式展示 AI 可读状态
6. 同步失败要展示失败原因并允许重试
7. 文档与治理资料同步更新纳入本次正式交付
