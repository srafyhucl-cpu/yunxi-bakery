**受控测试访问模式（CT-1A / CT-1 硬门禁，B1.9 定稿 + B2.0 + B3.1 + B3.2 补强）**

截至 **2027-05-31（含）** 只允许授权测试账号访问，当前任意成功微信登录的 `openid` 均能拿到 JWT、无后端强制边界。因此：

- **CT-1A / CT-1 定位（B3.2 前置）**：**CT-1A** 最小 fail-closed 围栏前置固定于 `FP-3a → CT-1A → FP-4A`——体验版连接真实后端前必须已落地（消除未授权访问窗口）；**CT-1** 完整硬门禁固定于 `FP-4A → CT-1 → FP-4B1 → FP-3b` 之间——**任何受控真实支付 / 退款测试（FP-3b）必须先通过 CT-1**；未落地围栏不得开展受控真实资金测试。
- 服务端访问模式设为 `controlled_test`，**fail-closed**（默认拒绝，白名单显式放行）：**唯一授权主体为 `principal_id = wx:<openid>`（B3 定稿）**——登录换取 JWT 时以 `wx:<openid>` 为 `sub`，**登录前与每次受保护请求均按同一主体校验**（不依赖手机号等可伪造字段，也不接受"openid 与 JWT sub 分属两套格式"的双主体解释）；**白名单持久化到 `controlled_test_whitelist` 表（B3）**：`principal_id`、`approved_by`（审批人，仅 project owner）、`valid_from / valid_until`（授权期限）、`revoked_at / revoke_reason`（撤销与原因）、`created_at / updated_at`——白名单外登录拒绝、白名单过期拒绝、已撤销拒绝、受保护请求逐请求校验白名单仍有效；模式与白名单变更留审计日志。
- **legacy header（B3 永久关闭）**：`x-miniapp-user-id` 等兼容头（`app/api/channels/storefront/_user.py`）**不再存在任何信任分支**——`STOREFRONT_AUTH_ALLOW_LEGACY_HEADER` 视为废弃（恒为 false），删除"关闭或同过白名单"的二选一表述；`authenticate_storefront_request` / `require_storefront_user_id` 只接受 Bearer JWT。
- **受保护 API 覆盖表（B3）**：CT-1 生效期间以下端点必须逐请求校验白名单——`POST /storefront/auth/login`（登录拦截）、订单（创建 / 详情 / 取消 / 支付）、充值（创建 / 确认）、组合支付、`POST /orders/{id}/apply-points` / `apply-coupon`、余额 / 积分 / 券查询（只读端点至少校验登录主体有效性）。实施时以实际 storefront 路由清单逐项核对，覆盖表入验收证据。
- **小额测试上限（B3 + B3.2 原子预占）**：受控真实测试设置**单笔上限 `CONTROLLED_TEST_MAX_SINGLE_FEN` 与累计上限 `CONTROLLED_TEST_MAX_ACCUMULATED_FEN`**（数值由项目负责人在裁决记录中固定），超限请求拒绝并审计；**（B3.2）累计上限按 `测试批次 × 主体（`principal_id`）× 币种（CNY）× 时间窗（裁决记录固定的测试期）` 统计，发起受控测试请求时对额度做原子预占**——单条条件更新 `controlled_test_quota`（`used + reserved + ? <= limit` 才放行并 `reserved += ?`，`version` CAS），预占失败即拒绝，测试数据清理（退款 / 状态恢复）完成后释放预占并计入 `used`——**并发受控测试不可能超累计上限**；与测试数据清理记录、退款、账务前后对账配套，确保可核对、可清理。
- **CT-1 拆门（B3.1 定稿 + B3.2 前置）**：**CT-1A 最小 fail-closed 白名单门**——2027-05-31（含）前与受控真实测试期间 fail-closed 白名单（本小节全部规则持续有效），**B3.2 前置至 FP-4A 之前生效**（体验版连接真实后端前已落地）；**CT-1 完整受控测试门禁**——FP-4A 后收口覆盖表核对 / 上限原子预占 / 审计 / 验收清单；**CT-1B 正式开放控制面**——FP-4B2 Go/No-Go 时由项目负责人批准将模式切换为 `open`（白名单拦截解除或降级为审计告警），以 FP-4B2 Go/No-Go 记录为准，切换本身登记证据（审批记录 / trace_id）。**不再使用"CT-1 持续有效"的未拆清表述**：CT-1A 自 FP-4A 起持续有效，CT-1B 开放控制面随 FP-4B2 生效且可审计。
- **微信体验者设置只能作为第二道防线**：服务端 `controlled_test` 白名单是主防线，不依赖小程序端体验者名单。
- **受控测试验收（B2.0 + B3 补齐）**：白名单登录拦截、过期、撤销、legacy header 绕过（**B3：legacy 头任意值一律 401，不再存在绕过面**）、切换 open 的负向用例；**受控真实测试记录须含退款结果、账务前后对账（前后余额 / 流水一致）、业务状态恢复（订单 / 券 / 积分恢复原状）与测试数据清理记录**；验收证据入证据索引。

## 支付关闭版本（仅限 FP-4B1，不面向真实用户）
