# 本地主动生产备份作业设计

> trace_id: `20260711-global-risk-remediation`
> 约束来源: 全局风险整改计划 R4-B、ADR 0005、用户确认本地 D 盘可作为长期备份位置

## 目标

在没有生产独立磁盘的前提下，由 Windows 本地主机每天主动拉取生产 SQLite 一致快照，并在 `D:\Backups\YunxiBakeBot` 形成经过完整性校验的 AES-256-GCM 加密备份。生产根盘只短暂保存随机命名快照，不作为长期备份位置。

## 方案

1. 通过 OpenSSH 在生产 `/dev/shm` 创建随机命名的 SQLite `.backup`，并执行 `PRAGMA integrity_check`。
2. 通过 SCP 拉取到本地备份目录下的随机明文临时文件。
3. 复用 `scripts/encrypted_backup.py` 创建不可覆盖的 `.ybak` 并立即解密校验。
4. 无论成功失败，逐个删除本地明文临时文件和远端临时快照。
5. 默认保留 30 天且至少保留最近 3 份；遵守删除红线，每次作业最多删除一个已解析并确认位于备份目录内的过期 `.ybak`。
6. Windows 计划任务每天 03:30 执行，仅在当前用户登录时运行，不保存系统登录密码；错过执行时在下次可用时补跑。

## 安全边界

- 密钥继续位于 `D:\Backups\YunxiBakeBot\keys\backup.key`，不得进入仓库或命令输出。
- JSON 报告只包含状态、备份路径、加密算法和清理结果，不包含客户数据、密钥或 SQLite 内容。
- SSH/SCP 参数按参数数组传递；远端路径由脚本生成，不接受用户提供的 shell 片段。
- Docker、云对象存储和生产持久挂载不在本工作包范围内。

## 验收

- 合成数据库合同测试证明成功加密、失败清理和单文件保留策略。
- 真实运行生成新 `.ybak`，`verify_encrypted_backup` 返回 `ok`。
- 生产 `/dev/shm` 和本地备份目录均无明文临时快照残留。
- 计划任务存在且命令指向仓库脚本、D 盘备份目录和仓外密钥。
