## Task 1：修复部署服务状态三态识别

**Owner:** OpenCode  
**Files:**

- Modify: `backend/scripts/deploy_server.sh`
- Modify: `backend/scripts/drill_deploy_rollback.sh`
- Modify: `backend/tests/scripts/test_deploy_server_contract.py`

### 问题

当前代码把 `systemctl is-active` 的所有非零结果都设置为 `SERVICE_WAS_ACTIVE="no"`。因此 systemd 查询失败、服务不存在、权限失败等情况会被误判为“发布前服务已停止”，导致回滚时错误保持停止状态。

### 执行步骤

- [ ] **1.1 编写失败演练**

在 `drill_deploy_rollback.sh` 增加以下桩状态：

- `active`：发布前服务运行；
- `inactive`：发布前服务确认停止；
- `unknown`：状态查询命令失败或返回未知状态。

新增失败断言：

- `unknown` 时不得切换到新版本；
- 不得执行 `git reset --hard bundle/master`；
- 不得停止或重启未知状态的服务；
- 输出明确的机器可读失败标记；
- 退出码非零。

先运行演练，确认当前实现能够复现该缺陷。

- [ ] **1.2 实现显式状态解析**

不要使用简单的 `if command; then ... else ...` 区分状态。使用 `systemctl show` 或等价可靠接口取得 `ActiveState`，至少区分：

```text
active   -> SERVICE_WAS_ACTIVE=yes
inactive -> SERVICE_WAS_ACTIVE=no
其他值   -> SERVICE_WAS_ACTIVE=unknown
查询失败 -> SERVICE_WAS_ACTIVE=unknown
```

未知状态必须在发布前直接拒绝：

```bash
if [ "$SERVICE_WAS_ACTIVE" = "unknown" ]; then
    log_error "无法确认发布前服务状态，拒绝继续发布"
    exit 1
fi
```

不得把查询失败降级为 inactive。

- [ ] **1.3 保留原有回滚合同**

确认以下行为不回归：

- 发布前 active：失败回滚后恢复运行并健康检查；
- 发布前 inactive：失败回滚后保持停止；
- 回滚成功输出 `ROLLBACK_STATUS=success`；
- 回滚失败输出 `ROLLBACK_STATUS=failed`、写告警并退出 `3`；
- 成功发布输出 `DEPLOY_STATUS=success`。

- [ ] **1.4 增加合同测试**

在 `test_deploy_server_contract.py` 增加静态断言，覆盖：

- `ActiveState` 或明确的状态查询逻辑；
- `SERVICE_WAS_ACTIVE=unknown`；
- 未知状态拒绝发布；
- `SERVICE_RESTORE_STATUS`；
- `ROLLBACK_STATUS`。

不要只依赖静态字符串断言，最终行为必须由演练验证。

- [ ] **1.5 执行验证**

```powershell
Set-Location D:\Project\YunxiBakery
bash -n backend/scripts/deploy_server.sh
bash -n backend/scripts/drill_deploy_rollback.sh
python -B -m pytest backend/tests/scripts/test_deploy_server_contract.py -q --no-cov
bash backend/scripts/drill_deploy_rollback.sh
```

证据输出：

```text
D:\Temp\yunxi-audit-final-20260906\drill-final6.txt
```

预期：退出码全部为 `0`，演练覆盖 active、inactive、unknown、启动失败、健康失败、脏工作区和依赖失败。
