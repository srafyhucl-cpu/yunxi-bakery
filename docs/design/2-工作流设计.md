# Bakery Commerce Platform — 渠道工作流设计

> 适用：团队 / 店员 核心问题：用户看到什么？人工怎么介入？订单怎么走？
>
> 说明：本文件主要描述渠道侧体验与人工介入流程，保留了较多 `Yunxi` 实例视角的业务表达。当前系统职责边界仍以 `docs/architecture/project-boundaries.md` 为准；如果流程描述与当前仓边界冲突，优先按 `Platform` 负责业务真相、`Storefront MiniApp` 负责前台渠道来理解。

## 一、总览：三个渠道，同一套 AI

```
用户（三个渠道）
  │
  ├── 小程序客服 ──→ AI 自动回复
  │                    └── 转人工 → 后台网页回复
  │
  ├── 企微 1 对 1 ──→ AI 以员工身份自动回复
  │                     └── 转人工 → 员工企微客户端直接回复
  │
  └── 企微群接龙 ──→ AI 自动识别汇总
                      └── 异常 → 店长群内纠正
```

## 二、小程序（有赞）

### 用户看到的样子

打开有赞微信小程序 → 点击客服 → 在客服聊天框里发送消息。

当 AI 推荐商品时，会以**微信原生的、高密度的独立连发消息段**返回，而非臃肿的单个大白框包裹：

```text
┌───────────────────────────────────────────────┐
│ ← Bakery Commerce Platform                     │
├───────────────────────────────────────────────┤
│ [用户]: 海盐奥利奥有图片吗                      │
│                                               │
│ [AI] 🍰: 有的呢，我就给您看看海盐奥利奥的图片~   │ ← 文字独立气泡 (带三角尾巴)
│                                               │
│       📷 [海盐奥利奥圆角大图]                  │ ← 高清大图 (独立消息，无背景框/三角)
│                                               │
│       💳 ┌───────────────────────────┐        │ ← 小程序分享卡片 (独立消息，左图右文)
│          │ 海盐奥利奥（芒果+奥利奥）  │        │
│          │ ┌───┐ 小程序 芸熙烘焙      │        │
│          │ │ 🎂│                      │        │
│          │ └───┘ ￥158.00             │        │
│          │ ─────────────────────────  │        │
│          │ 🟢 微信小程序        去下单 │        │
│          └───────────────────────────┘        │
│                                               │
│ [用户]: 我要转人工                            │
│ [AI] 🍰: 正在为您转接...                       │ ← 触发转人工
│ ═══ 客服小王已接入 ═══                          │
│ [小王] 🍰: 您好，我是客服小王，来为您处理~      │ ← 客服在后台回复
└───────────────────────────────────────────────┘
```

### 人工介入流程

```
用户要求转人工
  ↓
系统创建转人工工单（含对话摘要）
  ↓
通知客服 → 企微机器人推送 / 管理后台排队
  ↓
客服打开管理后台 → 看到待处理列表
  ↓
选择该用户 → 打字回复 → 发送
  ↓
用户在小程序聊天框收到客服回复
```

### 下单

小程序内有赞标准购物车流程下单，AI 只做咨询和查询，不介入下单操作。

## 三、企微 1 对 1

### 用户看到的样子

客户在微信上给店员「小张」发消息，**不知道对面是 AI**：

```
┌──────────────────────────────────┐
│           ← 芸熙烘焙 小张         │
├──────────────────────────────────┤
│ 李姐: 在吗？想订个蛋糕            │
│ 小张: 在的呢姐~想订什么样的？     │ ← AI 以"小张"身份回复
│ 李姐: 6寸草莓的多少钱             │
│ 小张: 6寸草莓168元                │ ← AI 回复
│ 李姐: 芋泥夹心，送到XX小区        │
│ 小张: 📋 您确认一下订单~          │ ← AI 提取订单草稿
│        6寸草莓 x1 芋泥夹心        │
│        XX小区3号  今天下午         │
│        没问题回复"确认"就下单      │
│ 李姐: 确认                       │
│ 小张: 已下单~做好给您发微信       │ ← 订单生效
└──────────────────────────────────┘
```

### 人工介入流程

采用**企微客户端直接回复**的模式，员工不需要打开任何后台：

```
客户发消息 → AI 正在自动回复
  ↓
员工"小张"在企微客户端看到该客户的消息
  ↓
特殊情况下（投诉、砍价、复杂定制）：
  → 企微收到转人工通知提示
  → 小张直接在企微客户端打字回复
  ↓
系统检测到小张已回复 → AI 自动停止
  ↓
后续对话归小张处理 → 直到小张手动交回 AI
```

**客户完全无感**：看到的始终是"小张"，不知道是 AI 在回还是真人在回。

### 下单流程

```
AI 识别到客户有下单意图
  ↓
AI 多轮对话收集：商品、数量、规格、配送地址、时间
  ↓
AI 生成订单草稿 → 发给客户确认
  ↓
客户回复"确认" → 订单写入系统 → 通知店员
  ↓
店员审核 → 安排生产
```

### 人工介入

群场景极少需要人工介入，主要是：

- **订单异常**：店长在群里 @ 纠正
- **投诉**：转为 1 对 1 私聊处理

## 五、转人工机制

### 什么情况会转人工

| 触发条件 | 识别方式 | |---------|---------| | 用户说"转人工/找客服/投诉" | 关键词识别 | | 用户情绪激动/不满 | LLM 感知语气 | | AI 连续 3
次答不上来 | 自动计数 | | 复杂退款/售后 | LLM 判断 |

### 客服怎么知道需要介入

统一通过 **企微机器人** 推送通知：

```
┌─────────────────────────────────────┐
│ 🤖 Bakery Commerce Platform 通知     │
│                                     │
│ 🔴 转人工请求                        │
│ 客户: 李姐                          │
│ 渠道: 企业微信 1 对 1                │
│ 原因: 要求打折                       │
│ 对话摘要: 李姐想订蛋糕，要求打折...   │
│ 👉 打开企微客户端回复                │
└─────────────────────────────────────┘
```

### 三种渠道的介入方式

| 渠道 | 客服怎么回复 | 工具 | |------|-------------|------| | 小程序 | 管理后台网页打字 | 浏览器 | | 企微 1 对 1 |
**企微客户端直接回复**（最自然） | 企微客户端 | | 企微群 | 群内直接回复 | 企微客户端 |

## 六、订单流转

### 订单状态

```
待确认 → 已确认 → 制作中 → 配送中 → 已完成
                         ↘ 售后处理
```

### 各渠道的下单方式

| 渠道 | 订单怎么产生 | 确认方式 | |------|-------------|---------| | 小程序 | 用户购物车自助下单 | 用户提交即生效 | | 企微 1 对 1 |
AI 从聊天提取 → 发给客户确认 | 客户说"确认" | | 企微群接龙 | AI 自动识别汇总 | 店长审核 |

### 订单信息

每个订单包含：客户、商品、规格、数量、金额、配送地址、时间、备注

订单写入系统后同步到店员可见的地方（腾讯文档或自建看板），店员据此安排生产。

## 七、完整流程示例

### 场景 1：小程序简单问答

```
用户发"提拉米苏多少钱？"
  ↓ AI 回复"48元~今日有货"
  ↓ 用户收到消息 → 结束
```

### 场景 2：小程序查订单

```
用户发"我的蛋糕到哪了"
  ↓ AI 调用有赞查询订单
  ↓ AI 回复"已出餐，正在配送"
  ↓ 用户收到消息 → 结束
```

### 场景 3：小程序转人工

```
用户发"我要投诉"
  ↓ AI 识别 → 创建转人工工单
  ↓ 回复"正在转接..."
  ↓ 通知客服 → 客服在后台回复
  ↓ 用户收到客服回复 → 进入人工服务
```

### 场景 4：企微 1 对 1 下单

```
客户发"来个6寸草莓蛋糕" → AI 回复"好的，需要什么夹心？"
  ↓ 客户回"芋泥" → AI 问"送到哪里？"
  ↓ 客户回地址 → AI 生成订单草稿发给客户确认
  ↓ 客户回"确认" → 订单生效 → 通知店员
  ↓ AI 回复"已下单~"
```

### 场景 5：企微 1 对 1 转人工

```
客户发"能不能便宜点"
  ↓ AI 回复"我帮您问一下店长..."
  ↓ AI 创建转人工 → 企微通知小张
  ↓ 小张在企微客户端看到消息，直接回复
  ↓ AI 停止 → 小张继续处理
```

## 八、API 对接说明

### 有赞 ✅ 可用

| 方向 | 方式 | |------|------| | 接收用户消息 | 有赞云配置消息推送，回调到 `https://yunxifood.cn/api/v1/webhook/youzan` |
| 发送回复 | 调有赞 API，以店铺名义回复到用户会话 | | 查订单/物流 | 调有赞订单查询 API |

管理后台回复的消息，会出现在用户小程序的同一个聊天框里，用户分不出是 AI 还是客服。

### 企业微信 ⚠️ 需要处理冲突

| 方向 | 方式 | |------|------| | 接收客户消息 | 企微配置回调 URL | | 发送消息 | 调企微 API，以员工身份发给客户 |

**冲突处理**：员工也在企微客户端时，AI 和员工可能同时回复。解决方案是 AI 生成回复后延迟 3-5 秒发送，检查员工是否已经回复了——如果员工回了，AI 取消发送。
