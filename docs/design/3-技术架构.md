## 三、核心对话流程（代码）

```python
# app/service/chat.py

async def handle_message(channel, user_id, content, staff_id="", raw_msg_id=""):
    """处理用户消息的主入口"""

    # 1. 去重（防止回调重复推送）
    if await message_repo.exists(raw_msg_id):
        return

    # 2. 获取或创建会话
    session = await session_repo.get_or_create(user_id, channel, staff_id)

    # 3. 保存用户消息
    await message_repo.save(Message(session.id, "user", content))

    # 4. 判断会话状态
    if session.status in ("transfer_pending", "human_service"):
        await handle_human_mode(session, content)
        return

    # 5. AI 对话循环（最多 3 轮 function call + 1 轮回复）
    for round in range(4):
        # 构建上下文：系统提示词 + 历史消息（滑动窗口 16K tokens）
        context = await build_context(session.id)
        # 调用 DeepSeek
        response = await llm_client.chat(context.messages, tools=FUNCTIONS)

        if response.finish_reason == "stop":
            # 纯文本回复 → 直接发送
            await message_repo.save(Message(session.id, "assistant", response.text))
            await send_reply(channel, user_id, response.text)
            return

        elif response.finish_reason == "tool_calls":
            # 工具调用 → 逐个执行
            for tool_call in response.tool_calls:
                result = await run_customer_tool(tool_call, session, user_id)
                await message_repo.save(Message(session.id, "tool", result,
                    tool_name=tool_call.function.name))
                if tool_call.function.name == "transfer_to_human":
                    return  # 转人工后结束循环

    # 超 3 轮 → 兜底
    await message_repo.save(Message(session.id, "assistant", fallback))
    await send_reply(channel, user_id, fallback)
```

### 滑动窗口算法

```python
def build_history(session_id, budget=16000):
    """从最新消息往回取，累计 token ≤ budget"""
    all_msgs = message_repo.get_all(session_id)
    selected, tokens = [], 0
    for msg in reversed(all_msgs):
        t = msg.estimated_tokens or estimate_tokens(msg.content)
        if tokens + t > budget:
            break
        selected.append(msg)
        tokens += t
    selected.reverse()  # 转回正序
    return selected
```

## 五、数据库设计（SQLite）

### sessions（会话表）

```sql
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    channel      TEXT NOT NULL,       -- youzan / wecom_1on1 / wecom_group
    user_id      TEXT NOT NULL,
    staff_id     TEXT DEFAULT '',     -- 负责员工ID
    status       TEXT DEFAULT 'active',
                   -- active / transfer_pending / human_service / closed
    extra_info   TEXT DEFAULT '{}',   -- JSON
    created_at   TEXT DEFAULT (datetime('now')),
    updated_at   TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_sessions_user ON sessions(user_id);
```

### messages（消息表）

```sql
CREATE TABLE messages (
    id TEXT PRIMARY KEY,
    session_id   TEXT NOT NULL REFERENCES sessions(id),
    role         TEXT NOT NULL,       -- user / assistant / system / tool
    content      TEXT NOT NULL,
    channel_msg_id TEXT DEFAULT '',   -- 渠道消息ID（去重）
    estimated_tokens INTEGER DEFAULT 0,
    tool_calls   TEXT DEFAULT '[]',   -- JSON
    tool_name    TEXT DEFAULT '',
    created_at   TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_messages_session ON messages(session_id);
```

### knowledge_base（知识库）

```sql
CREATE TABLE knowledge_base (

    keywords TEXT DEFAULT '',
    priority INTEGER DEFAULT 0,
    is_active INTEGER DEFAULT 1,
    created_at TEXT DEFAULT (datetime('now'))
```

## 七、消息类型与过滤

### 消息过滤规则

收到消息后先做类型判断，不是所有消息都丢给 AI：

```text
消息进入
  ├─ text              → ✅ 直接交给 AI 处理
  ├─ image             → AI 回复"请发文字描述，我看到后会帮您处理~"
  ├─ voice             → 🎤 标记为语音来源，调 ASR 转文字后给 AI（后期接入）
  ├─ voice_call        → ❌ 跳过，客服已直接接听
  ├─ video_call        → ❌ 跳过，客服已直接接听
  └─ system_event      → ❌ 跳过（撤回/已读/系统通知等）
```

### 语音消息处理方案（后期）

```text
用户发语音
  → 平台推送语音文件 URL
  → 服务器下载音频
  → 调腾讯云/阿里云 ASR 转文字
  → 结果标记 msg_source="voice_asr" + 置信度
  → 文字内容交给 LLM
```

**管理后台显示标记：**

```text
🎤 语音消息 | 置信度 92%
   转写: "来个6寸草莓蛋糕"
   📎 点击回听语音
```

**客服可点击原始语音链接跳转到企微/有赞后台回听**，避免转写错误导致误解。

### 启动自愈与向量校准架构 (Startup Lifespan Calibration)

系统在 lifespan 阶段加载了 BGE 密集向量模型，以实现高精度的本地 RAG 检索：

1. **加载模型**：在 CPU 上载入本地轻量级的高性能中文 Embedding 向量模型 `BAAI/bge-small-zh-v1.5`。
1. **拉取数据并解算**：自动从 SQLite 数据库的 `knowledge_base` 表中拉取所有在售 SPU（目前为 328 条活跃产品与服务）的物理行，转换成结构化 Markdown
   文本，逐一利用模型解算出 1024 维的高密 NumPy 实数特征矩阵。
1. **原子落库对齐**：通过多线程原子级写锁操作，同步将内存中的解算向量刷新并持久化到本地物理缓存，重构特征检索索引树，彻底杜绝数据库异动与向量矩阵的不一致。

### 自动化热部署流水线 (Automated Git Bundle Pipeline)

系统开发收尾并提交至本地 Git 后，通过高安全、极简的 **Git Bundle 物理合流** 流水线部署：

1. **打包增量**：本地执行 `git bundle create server.bundle HEAD`，将开发修改打包为标准二进制增量。
1. **无损合流**：通过 OpenSSH 的 `scp` 通道，秒级将 Bundle 推送至云服务器，并由 SSH 协力执行 `git fetch -f server.bundle HEAD`
   与强制硬指向 `git reset --hard`。
1. **零秒热重启**：最后通过 `systemctl restart yunxibakebot` 自动触发后台重启自愈，从而在极短时间内拉起新版本。
