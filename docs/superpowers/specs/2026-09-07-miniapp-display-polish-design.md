- 可视化过程稿：`.superpowers/brainstorm/967-1788755574/content/`（01、08、10、11、12 为关键对比）
- 上线红线：截至 2027-05-31（含）仅开发调试测试，不向真实用户开放；2027-06 只是最早候选窗口，需负责人明确批准

## S1 范围与不碰项

改：`miniapp/miniprogram/pages/products/`、`product-detail/`、`cart/`、`checkout/`、`orders/`、`order-detail/` 的展示层（WXML 层级 + WXSS + 文案层级）。

复用同一卡语言，不重构会员页；首页不动。

不碰：后端接口字段、后端业务逻辑、支付回调、订单持久化、商品同步、小程序 AppID 与密钥、第三方 UI 库不引入、渲染基线保持默认 WebView。

## S2 视觉语言（已锁定）

- 卡片：纯白实底 `#FFFFFF`，圆角统一 24rpx，无边框或极淡边框，阴影统一一档 `0 8rpx 24rpx rgba(44,37,32,0.10)`。
- 图片：列表图统一 1:1，`aspectFill` + 懒加载；圆角只收顶部 24rpx。
- 字阶：标题 28rpx/800/#1A1A1A 最多两行；销量规格 22rpx/#999999 一行；价格 38rpx/900/#111111，“起”22rpx/600/#999999 弱化。
- 徽标：左上小 pill，统一 20rpx/800，四类：招牌（黑底白字）、新品（金 `#C9A56A`）、热卖（深绿 `#4A7A41`）、限量（暖棕）。
- 主按钮：深绿渐变（沿用首页 `linear-gradient(135deg,#7BBA6E,#428036)`）+ 白字 + pill + 阴影；禁用态沿用现有灰绿，不断新色。
- 占位：中性暖米渐变（沿用详情页现有 `#F4F1EB→#FFFFFF→#E5DFD3` 系）加现有 `bakery-action-icon` 字形图标，删除 CSS 假蛋糕圆饼，不新增图片资源；有图缺图同一构图。

## S3 商品与交易表达（已锁定，以 08/10/11 屏右边为准）

- 列表卡：恢复被 `display:none` 藏掉的徽标，本地映射四类（首位商品为招牌，`tags` 含新品或限量关键字分别映射新品与限量，其余有 `soldText` 热卖文案映射热卖）；销量行直接使用现有 `soldText` 字段；标题两行收紧；销量与规格同一行灰字；价格行黑粗；列表“+”钮保持进入详情的真实行为，不改名、不做快捷加购。
- 详情首屏：1:1 沉浸大图；白底圆角价格条（价格 + 在售状态）；规格只做展示信息（横向 chips 白底，不做可选项）；须知卡白底；tags 小 pills；底部白底双钮（ghost 加购 + 深绿立即购买）。
- 购物车：行卡白底（小图 + 标题 + 步进）；推荐位沿用列表卡语言；底部 sticky 结算条（合计 + 去结算）。
- 结算：表单按收货、时间、备注分组白卡；券、积分、余额三行白卡；金额面板白底，实付黑粗 sticky；待支付条保留；协议行保留；提交钮深绿 sticky。
- 订单：筛选 tabs 深绿 active pill；订单卡白底；头部单号灰 + 状态 pills；标题 28rpx；收货与时间灰字；底部总额黑粗 + 详情链；操作区次按钮 ghost、主按钮深绿。

## S4 跟手交互（已锁定，以 12 屏为准）

- 按压：统一 `scale(0.97)` + 透明度 0.9，200ms 内。
- 骨架：列表 6 格、购物车 3 行、订单 3 卡，暖灰 shimmer，加载失败转空态加重试。
- 规格选择：一期不做。购物车按 `productId` 合并且无规格字段，订单只提交 `productId` 与数量；此时做规格弹窗会丢失规格语义并错误合并不同规格，造成订单内容错误。真实 SKU/变体交易拆为独立前置任务，本设计不覆盖。
- 步进器：统一 48rpx 圆形，减为描边、加为深绿实心；数量为 1 时减显示为删（沿用现有语义，只统一描边与尺寸样式）。
- 空错加载：统一插画 emoji + 标题 + 灰 hint + 深绿动作钮（去选购、查看全部、重试）。
- 图片失败：列表项、搜索结果、推荐位、详情、购物车分别维护图片失败态；`binderror` 后切换暖米占位并保持固定宽高，切换不引起卡片高度与按钮位置跳动；`imageUrl` 为空与运行时加载失败走同一占位分支。
- 键盘与安全区：结算页输入聚焦时提交条不被键盘遮挡；sticky 区域叠加 `safe-area-inset-bottom`；窄屏下价格与按钮不换行错位。
- 结算 sticky：金额与提交常驻底部，键盘与安全区按现有 `layoutStyle` 处理。

## 状态机（新增，与样式同等重要）

- 商品页：初始加载（骨架）/ 成功 / 空商品 / 加载失败 / 分类加载失败。新增页面级 `loadFailed` 与 `retryLoad`；主列表失败显示失败文案加重新加载，不白屏；分类失败时保留全部商品并显示分类降级状态。
- 订单页：沿用现有 `loadFailed`/`retryLoad`/`loadingMore`/`hasMore`；首次加载失败整页错误加重试，分页失败保留已加载订单只做行内提示，不清空列表；支付与取消逻辑不动。
- 结算页：保留“实付（估算）”语义与支付保护逻辑；待支付条、协议行保留。

## 数据流与契约

- 复用 `listProducts`、`getPublishedPageConfig`、`getShopSettings` 与现有 `specs`、`notices`、`tags`、`soldText`、`priceFen` 字段，不新增后端字段，不改 `miniapp/docs/api-contract.md`。
- 徽标四类、销量文案、规格选项全部本地派生；图片地址沿用现有 `API_BASE_URL` 补全逻辑。
- 后续若加促销字段，先更新契约再改 `services/` 与页面调用。

## 错误处理

- 缺图走暖米占位，不断布局；图片加载失败隐藏 `image` 切占位。
- 列表与订单接口失败走空态加重试，不留白屏。
- 加购失败 toast 提示并保留原态；规格缺失降级为直接加购。
- 结算提交失败保留表单与金额，不清空用户输入。
