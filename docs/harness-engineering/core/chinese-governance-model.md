# 中文治理六维模型

> 本模型是 Harness 的中文治理控制面。中文治理不是独立翻译项目，而是项目管理、工程驾驭和交付可复核性的共同约束。

## 目标

面向项目负责人、开发人员和接手 Agent 的内容，必须能直接读懂“现在是什么状态、谁负责、为什么阻塞、如何验证、证据在哪里、哪些内容尚未验证”。`task_id`、`trace_id`、`run_id`、`status`、路径、协议字段和命令原文保留稳定 ASCII，避免破坏机器接口。

## 六个维度

| 维度 | P0/P1 | 必须达到的结果 | 机器检查 |
|---|---|---|---|
| 文档 | P0 | 权威入口、状态、证据、交接和规则使用中文说明，旧镜像指向唯一入口 | 权威文件存在、中文标识和关键引用完整 |
| 系统界面 | P0 | 小程序和后台高风险页面的加载、错误、批准、阻断、支付和数据处理提示使用中文 | 用户可见文字扫描，技术标识白名单不计入缺口 |
| 协作沟通 | P0 | Issue、PR、交接和会议摘要都带任务、追溯、验证、证据和未验证范围 | 模板文件和必填字段检查 |
| 流程规范 | P0 | 启动、状态、门禁、审批和提交流程保持中文状态映射 | 规则入口、状态标签和 P0 命令检查 |
| 交付物 | P0 | 报告和证据同时说明结果正确、策略合规、证据完整、可回放 | 交付模板、manifest schema、证据索引检查 |
| 代码注释 | P1 | 新增或修改的自然语言注释使用中文，协议/工具指令保留白名单 | Python/TypeScript/WXML/CSS 注释扫描 |

## 判定口径

1. P0 维度任一必需文件、字段或高风险用户文案缺失，统一 Harness 门禁失败。
2. 代码注释属于 P1 全仓基线，但本轮新增或修改的自然语言英文注释仍按阻断处理。
3. `API`、`JSON`、`HTTP`、`URL`、`SKU`、`CNY`、`AI`、`Vue` 等协议或技术标识不要求翻译；它们不能替代中文的人类可读说明。
4. 通过检查只表示静态契约满足，仍要按验证矩阵执行运行测试、人工走查和负责人批准。
5. 六维优先级由机器契约锁定；协作模板的任务、追溯、验证和未验证字段按文件逐一校验，不能依靠多个模板合并后凑齐。

## 使用方式

```powershell
python -B backend/scripts/check_chinese_governance.py --summary
python -B backend/scripts/check_chinese_governance.py --json
```

报告会同时给出六维状态、文件覆盖率、界面英文文案缺口、英文自然语言注释缺口和未扫描的生成目录。历史低风险文案可以登记为 P1/P2，但不得把告警改写成已完成。
