## 一、收口范围

本轮只做三块，不再保留额外分支：

1. **Bug 1：成交口径修复**
   - 目标问法：`昨天已完成多少订单`
   - 结论：默认按“成交/有效订单口径”理解，不再把“已完成/完成”同时当作状态词和商品关键词。
   - 保留严格口径：只有明确说 `交易成功` 时，才走严格 `TRADE_SUCCESS`。

2. **Bug 2：预定/送达语义修复**
   - 目标问法：`有没有明天的预定订单`
   - 结论：`预定/预订/要送/待送` 统一按 `delivery_time` 解释，并默认落到待处理订单口径。
   - 同时清理 `有没有/没有/没/预定/预订` 等残留词，禁止再出现 `商品关键词“没 预定”`。

3. **阶段 3：按客户查（路 A）**
   - 只支持：员工在原话里带一个 **E 开头的有赞交易号**，再问“这个客户还买过什么 / 历史单”。
   - 路径：`E号 -> get_by_order_no -> buyer_id -> 按 buyer_id 查历史单`
   - 约束：复用已有 `ORDER_NO_PATTERN`，不新增普通数字解析，不做手机号/昵称查单。

## 二、最终规则

### 2.1 Bug 1：成交口径

- 当问法同时满足以下条件时：
  - 含下单日期语义，如 `昨天 / 今天 / 本周 / 本月`
  - 含 `已完成 / 完成`
  - **不含** `交易成功`
- 系统返回的订单状态集合改为“有效订单状态集”：
  - `WAIT_SELLER_SEND_GOODS`
  - `WAIT_BUYER_CONFIRM_GOODS`
  - `TRADE_SUCCESS`
- 同时这些状态词不再参与 `keyword` 提取。

明确保留：

- `昨天交易成功多少订单`
- `本周交易成功多少单`

这类问法继续走严格 `TRADE_SUCCESS`。

### 2.2 Bug 2：预定/送达语义

- 下列词命中时，日期字段统一改为 `delivery_time`：
  - `预定`
  - `预订`
  - `要送`
  - `待送`
- 当这类语义命中且用户未显式给状态时，默认补待处理状态集：
  - `WAIT_SELLER_SEND_GOODS`
  - `WAIT_BUYER_CONFIRM_GOODS`
- 下列词必须从订单关键词提取中剔除：
  - `有没有`
  - `没有`
  - `没`
  - `预定`
  - `预订`
  - `要送`
  - `待送`

目标效果：

- `有没有明天的预定订单`
  - `date_field=delivery_time`
  - 日期=明天
  - `statuses=待处理状态集`
  - `keyword=""`

### 2.3 按客户查（路 A）

- 只在同时满足以下条件时触发客户历史单分支：
  - 原话里命中一个 `E` 开头有赞交易号
  - 原话里命中“客户历史单”意图词，如：
    - `这个客户`
    - `该客户`
    - `还买过`
    - `历史单`
    - `历史订单`
    - `买过什么`
- 单独一个 `E` 号，仍保持当前“查这笔订单详情”行为，不切到客户历史单。
- 客户历史单链路中：
  - `OrderQueryPlan` 新增 `buyer_id`
  - service 层用 E 号先查原订单，再把 `buyer_id` 写入 plan
  - repository 层只按 `buyer_id = ?` 过滤
  - 回复中统一用“该客户”表述，不回显 `buyer_id`

异常口径：

- E 号不存在：
  - 明确提示“未找到该交易号，无法继续查该客户历史订单”
- E 号存在但只有这一单：
  - 仍正常返回 1 单

- 补送达语义词
- 补停用词
- 补“预定订单默认待处理状态”规则
- 补对应单测

### 阶段 2：Bug 1

- 清掉弱完成词的关键词残留
- 保留“交易成功”严格状态口径
- 补对应单测

- 回复使用“该客户历史订单”口径
- 无效 E 号给明确提示
- 补对应单测

## 五、验收标准

1. `昨天已完成多少订单` 不再残留 `已完成` 关键词，并按有效订单状态口径统计。
2. `昨天交易成功多少订单` 仍走严格 `TRADE_SUCCESS`。
3. `有没有明天的预定订单` 解析为 `delivery_time + 明天 + 待处理状态 + 空 keyword`。
4. `E2026... 这个客户还买过什么` 能列出同 `buyer_id` 历史单。
5. 无效 E 号返回明确提示，且回复不泄露 `buyer_id` 原值。
