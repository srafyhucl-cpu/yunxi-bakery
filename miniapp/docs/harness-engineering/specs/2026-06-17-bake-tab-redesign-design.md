## 目标

基于参考图 2 的整体视觉语言，重构微信小程序五个 Tab 页面的信息层级、卡片排布和模块节奏，让当前 MVP 页面从“功能可用”提升到“接近品牌级烘焙商城首版视觉稿”。

本轮设计先解决三件事：

1. 用统一视觉母版重排 `home`、`products`、`cart`、`chat`、`profile` 五个页面。
2. 先产出一份可直接打开的 HTML 原型，同时提供宫格布局图和高保真排版图。
3. 为后续小程序实现明确共享样式、页面结构和配置落点，避免逐页复制样式。

## 范围

### 在范围内

- 五个 Tab 页面：`pages/home/index`、`pages/products/index`、`pages/cart/index`、`pages/chat/index`、`pages/profile/index`
- 页面视觉语言统一：背景、圆角、阴影、标题、卡片、导航状态、底部 tab 视觉
- 模块层级重排：Banner、分类宫格、商品卡、购物车卡、服务卡、我的页菜单
- 先行原型资产：一份静态 HTML 设计稿

### 不在范围内

- 后端 API 字段扩展
- 商品详情页、订单页、结算页深度重构
- 真机截图证据和微信开发者工具手工验收
- 新引入第三方 UI 库

## 页面结构设计

### 首页 `home`

首页使用“品牌横幅 + 分类宫格 + 精选推荐”的结构：

1. 顶部 Hero 为横向品牌主视觉，左侧放品牌语和英文副标题，右侧放主蛋糕视觉。
2. Hero 下方是四宫格分类入口，对应蛋糕礼盒、下午茶甜点、每日欧包、企业订制。
3. 中段使用“精选品推荐”标题条，进入双列瀑布式商品陈列。
4. 商品卡采用大图优先，标题和价格贴底，形成图 2 中杂志式编排感。
5. 底部 tab 保持原生结构，但视觉上用浅金激活态。

### 商品页 `products`

商品页采用“顶部分类导航 + 双列商品流”：

1. 顶部使用一行图标分类，支持横向感知当前品类。
2. 主体区域为双列商品卡，每张卡突出大图、标题和价格。
3. 商品卡右下角保留轻量加购按钮，呼应参考图的金色小圆按钮。
4. 页面不再强调长段说明，长说明降级到页尾低优先级区域。

### 购物车页 `cart`

购物车以“纵向购物项 + 固定结算栏”为主：

1. 每个商品项都是独立白卡片，左图右文，价格和数量步进器分层排布。
2. 左侧保留选中态圆点，弱化列表感，强化卡片感。
3. 底部固定结算栏采用浅色浮托底，左侧总价，右侧金色主按钮。
4. 购物项数量不多时，也维持较大留白，接近参考图 2 的呼吸感。

### 客服页 `chat`

客服页重构为“欢迎头图 + 三张服务入口卡片”：

1. 顶部使用烘焙工坊场景图，作为品牌感欢迎区。
2. 中间保留“欢迎询问”标题，形成视觉中轴。
3. 下方三张卡片分别承载配送政策、订购流程、售后服务。
4. 若未来恢复即时聊天，可把输入面板下沉为二级交互，而非当前整页主视图。
5. 本轮设计优先满足参考图式的服务入口页，而不是聊天记录页。

### 我的页 `profile`

我的页使用“头像区 + 订单管理 + 两列功能菜单”：

1. 顶部为圆形头像和用户名，居中排列。
2. 第一张卡片为订单管理，四个状态入口横向平铺。
3. 第二张卡片为功能菜单，两列网格组织常用入口。
4. 整体弱化技术态字段展示，例如当前 `session userId` 等调试信息不作为主视觉内容。
5. 保留后续接地址、优惠券、礼品卡、设置、联系我们等能力入口。

## 配置与数据映射

本轮视觉改造尽量复用现有配置数据，不先扩接口：

- `home` 继续以 `heroCarousel`、`categoryGrid`、`productShelf` 为主，但映射为新视觉模块。
- `products` 继续复用商品列表和分类配置，调整成顶部图标导航 + 双列卡片。
- `cart` 继续读取本地购物车数据，仅重排布局。
- `chat` 当前服务页可由本地静态配置先承载，后续再与在线聊天模式切换。
- `profile` 继续读取 `memberSummary` 和服务入口，但隐藏不适合主视觉的调试字段。

## 小程序落地原则

### 实施顺序

1. 先沉淀共享视觉 token 和通用卡片样式。
2. 再改首页和商品页，建立统一商品卡。
3. 然后改购物车和客服页。
4. 最后改我的页，统一订单宫格和菜单栅格。

### 代码边界

- 页面业务加载仍放在各自 `index.ts`
- 共享静态配置优先放 `miniprogram/config/`
- 共享视觉样式优先抽到组件或全局 token
- 不在页面内新增大段魔法颜色和重复间距值

## 验收标准

设计稿阶段完成标准：

1. 存在一份可直接打开的 HTML 原型文件。
2. HTML 同时包含宫格布局图与真实排版图。
3. 五个页面的结构、视觉语言和重点模块与参考图 2 保持统一。
4. 设计说明明确了共享组件、视觉 token 和落地顺序。

代码实现阶段验收另行编排，不在本设计稿中展开。

## 风险与后续

- 当前高保真原型使用静态烘焙风格图形模拟，真实上线仍需替换为门店正式商品图和人物图。
- 客服页当前参考图更像“服务导航页”，若后续要兼容在线聊天，需要设计二级态或切换态。
- 我的页现有技术态字段较多，真正落版时需决定是否彻底迁出 UI。
