# Reuse and Configuration Rules

本规则用于约束小程序页面开发，避免为了快速复刻页面而产生重复代码、魔法值和不可维护的页面逻辑。

本仓是 `Storefront MiniApp` 前台渠道仓。页面、组件、工具和 service 都只能服务前台体验；客户、商品、订单、AI 会话、店铺配置和第三方同步的业务真相属于 `Platform` 主仓。

## 核心原则

1. 页面负责组合，不负责定义业务真相。
2. 重复出现两次的结构、文案、状态或行为，要优先沉淀为配置、组件或工具。
3. 任何后续可能被门店、活动、接口或环境影响的值，都不要直接写在页面里。
4. 先复用项目内能力，再考虑新增抽象；新增抽象必须能减少真实重复或让边界更清楚。

## 配置优先

以下内容必须优先集中管理：

- 页面路由、tab key、入口文案和跳转目标。
- 店铺名称、客服电话、客服微信、公告文案、订购须知。
- 分类、货架分组、会员服务入口、空态推荐区。
- 订单状态、支付状态、配送方式、会员权益类型。
- 颜色、间距、圆角、卡片阴影等长期重复的视觉 token。

推荐位置：

- `miniprogram/config/`：业务配置、页面入口、店铺信息、视觉 token。
- `miniprogram/constants/`：状态枚举、storage key、route path、事件名。
- `miniprogram/types/`：跨页面共享的数据结构。

## 组件与工具

优先抽离这些重复单元：

- 商品卡、货架分组、分类入口、公告条、会员摘要、服务入口宫格。
- 空态、加载态、错误态、底部结算栏、数量步进器。
- 金额格式化、购物车本地状态、订单 payload 组装、路由跳转辅助。

推荐位置：

- `miniprogram/components/`：可跨页面复用的 UI 组件。
- `miniprogram/utils/`：纯函数、storage、本地状态和格式化。
- `miniprogram/services/`：只放 HTTP API 调用、参数组织、接口适配和前台兜底，不沉淀 Platform 业务规则真相。

## 页面约束

页面文件应尽量保持小而清晰：

- `index.ts` 负责加载数据、响应事件、调用工具或服务。
- `index.wxml` 负责组合组件和配置驱动的列表。
- `index.wxss` 只放页面独有布局；重复样式优先提升到全局样式或组件样式。

避免：

- 在多个页面复制商品卡结构。
- 在页面内写死客服电话、分类名称、tab 文案、storage key。
- 在 WXML 中堆复杂条件判断和状态翻译。
- 为了单个页面引入第三方 UI 组件库。

## 变更检查

开发前先问：

- 这个值是否会在别处用到？
- 这个结构是否已经出现过？
- 这个状态是否应该成为枚举或类型？
- 这个逻辑是否属于页面，还是应该放进工具、组件或服务？

收口前检查：

- 没有新增明显魔法字符串或魔法数字。
- 重复 UI 至少有抽离计划；已出现两次的优先抽离。
- 新增配置有类型约束，调用方不直接猜字段。
- 若暂时保留重复，必须在 LOGBOOK residual_risks 中写明原因。
